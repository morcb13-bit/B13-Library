# 第19章　探す：二分法と最短路

## 19.1 半分にして比べる

探すことの一番簡単な形は、幅を半分にして、目当てがどちら側にあるかを比べることです（二分法）。

```python:code/b13_search.py
def bisect_isqrt(n):
    """x·x ≤ n となる最大の x。"""
    lo, hi, steps = 0, n + 1, 0
    while hi + -lo > 1:
        mid = half(lo + hi)              # 半分は倍々の梯子（第6章）
        steps += 1
        if mid * mid <= n:
            lo = mid
        else:
            hi = mid
    return lo, steps
```

| 探したもの | 答え | 比べた回数 |
|---|---|---:|
| x·x ≤ 1000000 の最大の x | 1000 | 20 |
| x·x ≤ 2 × 10⁶⁰ の最大の x | 1414213562373095048801688724209 | 201 |
| x³ − 2x − 5 = 0 の根（目盛り S = 10⁴⁰） | 2.094551481542326591482386540579… | 133 |

一回比べるごとに幅が半分になるので、比べる回数は、幅を 2 で何回割れるかで決まります。第9章では √n を「奇数を引けるだけ引く」で出しました。二分法は、同じ答えを「半分にして比べる」で出します。

## 19.2 フィボナッチで切る

半分にする代わりに、幅をフィボナッチ数で切ることもできます。

- 列の長さを越える最初のフィボナッチ数 F(k) を用意します。
- F(k − 2) 番目と比べ、目当てが右にあれば幅を F(k − 1) に、左にあれば F(k − 2) に縮めます。
- 次のフィボナッチ数は、手元の二つの引き算で出ます。割り算も半分にすることも要りません。

1, 4, 9, …, 1000000（1000 個の平方数）の中から、1000 個すべてを探しました。

| | 比べた回数の最大 | 比べた回数の合計 |
|---|---:|---:|
| 二分法 | 10 | 8987 |
| フィボナッチ | 14 | 9730 |

フィボナッチで切るほうが、比べる回数は少し多くなります。その代わり、使う操作は足し算と引き算だけです。

## 19.3 床の上で探す

列の中を探すときは、左か右かの二択でした。床の上（ペンローズの頂点と辺、第18章）で探すときは、どの番地にも 3〜7 の隣があります。

第18章では、波の先頭が「最短の段数」（壁を避けて隣をたどったときの段数）に沿って進むのを見ました。この章では、波を使わずに、足し算と比べることだけで最短の道を見つけます。

床は第18章と同じ作り方で、少し小さく取ります（番地 2910 個）。右寄りに餌を一つ、左寄りにアメーバの種を四つ置き、あいだに壁を立てます。

## 19.4 餌の濃さは、全部の道に均等に広がる

餌の濃さ D を、次の一行で広げます。

```
D_t(i) = Σ（通れる隣 j の D_{t−1}(j)） ＋ （i が餌なら k^t）
```

どの番地も、毎刻、通れる隣の濃さを足すだけです。餌の番地には、毎刻 k^t を注ぎ足します（k は 8）。

```python:code/b13_search.py
for v in range(n):
    if wall[v]:
        continue
    s = 0
    for u in adj[v]:
        if not wall[u]:
            s += D[u]
    N[v] = s
N[food] += kt
kt = kt * k
```

この D は、**餌からその番地へ至る、すべての道の寄与の和**になっています。長さ L の道を通って届く分には、L 歩前に注いだ k^(t − L) が乗るので、長い道ほど小さく効きます。餌は道を選ばず、通れる道すべてに広がります。壁は越えません。

## 19.5 アメーバは濃い方へ寄るだけ

アメーバの規則は一行です。

- 今いる番地の隣のうち、いちばん濃い番地へ移る。濃さがぴったり等しい隣が二つあれば、両方へ進む。
- 濃い隣がなければ、止まる。

アメーバは道を比べていません。道を比べる仕事は、餌が全部の道に広がる段で済んでいます。

壁の置き方を変えて、四つの種から餌までの歩数を数えました（160 刻広げた濃さで）。

| 壁の置き方 | 種 1 | 種 2 | 種 3 | 種 4 |
|---|---|---|---|---|
| 隙間は上 | 75 / 75 | 69 / 69 | 66 / 66 | 64 / 64 |
| 隙間は下 | 65 / 65 | 63 / 63 | 68 / 68 | 72 / 72 |
| ジグザグ（壁 3 枚） | 81 / 81 | 75 / 75 | 70 / 70 | 66 / 66 |

（アメーバの歩数 / 最短の段数）

どの地図でも、四つの種すべてが最短の段数ちょうどで餌に着きました。

対照を二つ置きました。

- **壁を無視して広げた濃さ**では、アメーバはほとんどが壁の手前で止まります。着いたのは、まっすぐ進めば隙間を通る種だけでした（隙間は上で種 4、隙間は下で種 1）。
- **隙間をふさぐ**と、種の番地の濃さは 0 のままで、アメーバは動きません。「道がない」ことが、濃さ 0 としてそのまま分かります。

## 19.6 注ぎ足しの倍率

注ぎ足しの倍率 k を変えて、壁の手前の番地も含め、床の全部の番地を種にして試しました。数は、最短の段数ちょうどで餌に着いた番地の数です。

| 壁の置き方（番地の数） | k = 4 | k = 5 | k = 6 | k = 7 | k = 8 | k = 9 |
|---|---:|---:|---:|---:|---:|---:|
| 隙間は上（2822） | 0 | 2817 | 2821 | 2822 | 2822 | 2822 |
| ジグザグ（2826） | 0 | 2597 | 2825 | 2826 | 2826 | 2826 |

k が 7 以上では、二つの地図のどの番地からも、最短の段数ちょうどで着きました。7 は、この床の番地が持つ隣の数の最大です。k = 4 では、一つも着きません。注ぐ量が小さいと、濃さは短い道より長い道の数で決まってしまうからです。

## 19.10 観察者側の整理

既存の数学の名前との対応です。確かめた範囲の行のほかは、Claude の知識によるもので、この本では検算していません。この章は、既存の探索の方法を整数の操作で並べたもので、それ以上のことは主張しません。

- 19.1 は二分法（二分探索）です。x³ − 2x − 5 = 0 は、ニュートンが自分の方法の例に使ったことで知られる式です。
- 19.2 はフィボナッチ探索（キーファー、1953 年）で、黄金分割探索の整数版にあたります。
- 最短の段数を隣から一段ずつ広げて数えるのは、幅優先探索です。
- 19.4 の D は、隣どうしのつながりを表す表を A とすると、Σ A^L / k^L の形の和（「すべての長さの道の数」を k で割り引いて足したもの）にあたります。ネットワーク分析のカッツ中心性と同じ形です。この和が収まるには、k が A の最大の固有値より大きい必要があります。19.6 で k = 4 が一つも着かなかったのは、これに関係していると考えられます（固有値そのものは計算していません）。
- 濃さの場を登って目的地へ向かうやり方は、ロボットの経路計画で「ポテンシャル場」と呼ばれる方法の一つです。粘菌が迷路の最短路を残すことは、中垣俊之らの実験（2000 年）で知られています。
- アメーバがいつでも最短の段数で着くことは示していません。確かめたのは、19.5 と 19.6 の地図と番地についてだけです。

## 19.11 この章のまとめ

探すことは、比べることと足すことでできます。

- 二分法は、幅を半分にして比べることを繰り返します。比べる回数は、幅を 2 で割れる回数です。
- フィボナッチで探すと、半分にする代わりに、二つ前のフィボナッチ数を引くだけで幅を縮められます。
- 床の上では、餌の濃さを「通れる隣を足す」だけで広げると、濃さは全部の道の寄与の和になります。
- アメーバは濃い方へ寄るだけで、試した地図では最短の段数ちょうどで餌に着きました。注ぎ足しの倍率は、隣の数の最大より大きく取ります。
